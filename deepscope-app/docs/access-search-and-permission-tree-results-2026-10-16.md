# 用户/角色筛选、日期时间面板与授权样式

对应计划：`docs/superpowers/plans/2026-10-16-access-search-and-permission-tree.md`。

## 已完成

- 用户搜索新增昵称与创建时间，角色搜索新增创建时间；仍为草稿提交模式，清除重置所有条件及页码。昵称使用现有 SQL 模糊匹配转义，时间过滤在 COUNT 和分页之前执行。
- 用户和角色文本框提示统一“输入字段名”；查询使用紫色主按钮，清除保留白色描边。
- 根据用户补充参考图，将独立日期框替换为一个组合时间范围框。弹层有今天、最近 7 天、最近 30 天、昨天、本周、本月、上周，日历及可滚动时/分/秒列，支持年月导航、输入与清除。
- 范围先在弹层编辑，确认后更新表单草稿，查询时才发送后端。Enter 确认范围不误提交表单，Escape 取消未确认选择并返回日历触发按钮；输入时保留焦点，按钮打开面板时允许键盘进入内容。
- 日期按本地时区解释，开始包含，结束秒包含并换成后端排除边界；只填结束日期时包含当天，支持单侧范围、拒绝非法或倒置范围。
- 用户/角色编辑与重置密码标签使用深灰、输入内容使用更深文字。权限树默认折叠，展开不改变勾选；全选、半选、只读和管理员必留权限保持。勾选紫色调浅，确认按钮浅紫底深色字。

- 后端：AccessFiltersTest、AccessPaginationTest、AccessManagementTest、AccessCatalogTest、ManagementPaginationTest 合计 26 项通过；覆盖字面 %/_ 昵称、时间范围起止边界、第二页、单侧时间、非法/倒置时间。
- Spotless、git diff --check 通过；Lint 0 error、43 项既有 warning；TypeScript 与 Vite Build 通过，保留包体积提示。
- 独立审查发现混合时间输入的边界错误，已先复现“同日中午开始＋仅结束日期”失败，再修复为先计算排除边界后校验，审查确认关闭。
- 使用现有 Radix Popover、Input、Button；项目无日历组件，新增精确版本 react-day-picker 10.0.2（React 18 兼容，MIT），锁文件只增加其依赖。审计未发现新增三个包的公告；仓库审计仍有既有 4 moderate、6 high，未扩大范围执行依赖修复。
