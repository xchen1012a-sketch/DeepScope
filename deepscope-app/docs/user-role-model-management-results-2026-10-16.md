# 用户、角色与模型管理实施结果

对应方案：`docs/superpowers/plans/2026-10-16-user-role-model-management.md`。

## 界面与交互

- 用户和角色页按用户提供的芋道参考图调整：紧凑横排搜索卡片、独立列表工具栏、新建按钮、编辑/删除/更多文字操作。使用共享 `DataTable`、`TableToolbar`、`TableActions` 的配置与变体，没有引入第二套表格。
- 用户字段显示“账号”，角色字段显示“角色标识”；补充真实编号、备注、创建时间，角色另有类型和排序，移除人数列。没有添加接入模型、手机号、部门等项目尚无的数据。
- 搜索与状态/角色筛选先保留草稿，提交或回车才查询后端；清除回第一页。下拉面板与触发框等宽。
- 用户更多菜单提供分配角色、重置密码、启停；角色更多菜单提供授权、启停。删除需要确认，失败保留弹窗与错误。
- 授权弹窗从服务端读取页面/操作树和当前权限，支持全选、半选、失败保留、重开刷新，内置角色只读。
- 模型新增完整配置复制，包含密钥；直接写入剪贴板，不放入页面状态或 Query/Mutation 缓存。复制响应设置 no-store，错误只显示重试提示。
- 服务商选择提取为 `ServerProviderSelect`，模型配置和列表筛选共用后端搜索。模型列表按具体服务商预设筛选，避免把共享 OpenAI 协议的不同厂商混为一类。
- 向量预设补充智谱和 Mistral。向量候选仅接受已核实 ID 或明确返回的向量能力，发现缓存按 kind 隔离，保存校验向量响应与维度。未分类模型可手动输入后验证。

## 权限与账号保护

- 保留旧 manage 权限含义；操作权限由后端实际路由校验，模型、用户与角色按钮同步控制，资源归属检查保留。
- 未知权限拒绝保存；角色停用后不会恢复旧的无角色默认权限。
- 分配角色需 role.grant；普通用户编辑者不能修改或接管拥有其未持有权限的账号。
- 继承已保存密钥时绑定原地址和认证协议；修改连接必须重新输入密钥。路径附加矩阵参数不能绕过复制权限。
- 内置账号不能停用，内置角色不能停用、删除或修改授权；最后一个超级管理员保护保留。
- 本地实际发现 admin 账号已停用，已仅恢复其 status=active，未修改密码。Admin 角色本来就是启用状态。
