### 3. 会话卡死 + 「Thread already has an active run」修复（commit 5b11499）
根因：模型 HTTP 调用卡死 → 无事件产出 → SseEmitter 无法感知客户端断开 → `AguiResumeCoordinator` 的内存 active-run 标记永久泄漏。三层修复：
- **Layer 1**（应用层）：`AdvisorConfiguration.java` 的 chatModel Bean 注入 `JdkHttpTransport`，连接 10s、响应/读取/流空闲 120s。
- **Layer 2**（starter 层）：`AguiMvcController` 每 15s 发 SSE 注释帧心跳，写失败即走断连中断路径；间隔可配 `deepscope.agui.heartbeat-interval`（0 关闭）。
- **Layer 3**（协议层）：`AguiRequestProcessor` 事件流应用 `config.getRunTimeout()`（配置已有 `run-timeout: 10m` 但此前从未生效），超时切换为 RUN_ERROR 事件流（错误码 TIMEOUT_ERROR），不再发重复 RUN_STARTED。
- 前端：`ConversationPanel.tsx` 的 `friendlyRunError()` 把超时/并发冲突错误映射为本地化文案，词典键 `chat.errorTimeout` / `chat.errorBusy`（中英已同步）。

## 五、下一步：模块三「受控斜杠命令体系」

方案见 `advisor_features_plan.md` 第四节，要点：
1. **命令注册表**：数据库新表，字段含命令代号/名称/描述、来源（builtin 全员共享 / custom 按用户隔离）、路由类型（target_type + target_id）、启用状态与排序权重。
2. **四类路由**：action（本地动作，零 Token，如 `/compress` 可复用模块二的压缩服务）、skill（技能注入）、mcp（单工具精准挂载）、prompt（模板展开）。
3. **输入框自动补全**：键入 `/` 弹 Radix 浮层，实时过滤 + 键盘导航（↑↓/Enter/Tab/Esc）。

注意：`/compress` 动作型命令应直接复用已实现的 `SessionCompactionService`，不要重复实现压缩逻辑。

## 六、经验教训（避坑）

1. **调研克制**：读够动手所需的文件即止，不要反复搜索无关内容——此前因过度调研被两次批评进度慢。
2. `OpenAIChatModel.Builder` 只有 `httpTransport(HttpTransport)`，没有 httpTransportConfig 方法，要传 `JdkHttpTransport.builder().config(...).build()`。
3. 新 Java 文件先 `spotless:apply` 再过门禁，否则格式检查必挂。
4. H2 测试 URL 必须带 `DB_CLOSE_DELAY=-1`。
5. 前端 TS target ES2020，没有 `.at()` 类型，用索引访问。
6. 进行态测试用受控 Promise 手动 resolve，避免 mock 立即 resolve 造成时序不稳。
7. 工具结果豁免清理名单新增条目要谨慎评估体积，会阻止历史内容被压缩淘汰。
8. 后端启动不带 `--spring.datasource.username=juvon` 会因默认角色不存在而失败。
