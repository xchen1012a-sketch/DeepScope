## 1. 背景与目标

### 1.1 这一轮要做什么

把「会话」模块与会话页按 DeepSeek Harness 重建。允许推翻既有设计。三项一起换：

1. `agentscope-core` 的日志内核；
2. `agentscope-harness` 的会话编排（`AgentSession`）；
3. 会话页界面（对话流、深度思考行、工具行、输入区）——**界面也在复刻范围内**（见第 5 章）。

既有消息模型（`Msg` 与内容块体系）保持不变，只对齐其上的投影与派生层。

### 1.2 为什么要换

现有实现的问题不在缺功能，而在**权威来源放错了位置**：恢复依赖 checkpoint 里那一整坨序列化状态，日志退居为"顺带记下的过程"。由此产生四个直接后果：

1. **不可重放**：当时到底发了什么给模型，日志里没有记录，无法精确重建。
2. **压缩即丢失**：上下文压缩改写工作副本，被压掉的原文在可见层面消失。
3. **事件无主次**：57 类内置事件平铺，产消息的与纯诊断的混在一起，扩展只能往这张大表里加。
4. **恢复路径与读取路径分叉**：恢复读 checkpoint、界面读事件流，两条路各算各的，容易不一致。

DeepSeek Harness 的做法正好逐条对治：日志是唯一权威，其余全部是派生；压缩只遮蔽不删除；事件按族分级，扩展自带；恢复就是把日志重新折一遍。

### 1.3 交付目标

- 模型历史、界面视图、统计、标题、检索索引、崩溃恢复**全部由同一份日志派生**。
- 每一次模型请求可由日志精确重建。
- 上下文压缩不破坏原始记录。
- 持久化后端可替换，换后端不动上层。
- 会话页的对话流、深度思考行、工具行、回合折叠、输入区统计与上下文环，**在数据与呈现两层都对齐 DeepSeek Harness**（见第 5 章）。

### 1.4 明确不做

- 不替换 `Msg` 与内容块体系（`ContentBlock`、`ToolUseBlock`、`ToolResultBlock`、`ThinkingBlock` 等保持现状）。
- **不兼容既有磁盘日志**：新格式只认新日志，不提供旧日志迁移与导入。
- 不引入 DeepSeek Harness 的技术栈假设（不引入 Reactor 之外的新运行时、不引入 Cordis 式的插件容器）。
- **不把 DeepSeek Harness 的客户端整体搬进来**：不搬它的插件槽与注册表容器、会话日志设置页、三车道轨迹图、配额与账号通知链、鲸鱼运行指示与品牌图标、桌面端专属行为。界面按"呈现与交互对齐、按本仓库技术栈重写"的方式复刻（边界见 5.5）。
- 不引入 DeepSeek Harness 的业务专属分类表（工具名到过程类目的映射表、子智能体与交付物等业务卡片），这些按本仓库的工具集重新定义。

## 2. 现状与目标对照

### 2.1 结构对照

| 维度 | 现状 | 目标 |
| --- | --- | --- |
| 权威来源 | checkpoint 即恢复点，事件为过程记录 | 日志即真相；"模型看得见 ⟺ 日志里记了" |
| 事件模型 | 57 类内置事件平铺 | 按族分级：产消息的 / 生命周期的 / 诊断的 / 扩展的 |
| 模型历史 | 来自 checkpoint 反序列化出的工作副本 | 由日志增量折出一份对话节点列表 |
| 上下文压缩 | 改写工作副本，被压内容不可见 | 记一条替换动作遮蔽原文，原文永久保留 |
| 请求可重放 | 无（未记录请求信封） | 每次请求整体快照入日志，可精确重建 |
| 回合模型 | turn 与 run 两级，一次任务可多次 run | 回合 = 一次执行；步骤 = 一次模型调用及其工具 |
| 崩溃恢复 | 读 checkpoint | 折日志，补记未闭合回合与无结果工具调用 |
| 持久化接口 | 提交链 + 头 CAS + 写者租约 + 永久封禁 | 句柄式：建/开/看/列/冲刷；冲刷即耐久屏障 |
| 磁盘形态 | 提交批次 + 外置 blobs + 独立 inbox | 一会话一目录一追加日志，文件带格式版本号 |
| 派生视图 | 恢复视图 + 若干手写读取器 | 统一投影注册表，领域各注册一个折叠函数 |
| 检索 | 无（现有工具仅按会话读消息） | 独立全文检索后端 + 统一查询服务 |

### 2.2 必须保留的硬语义

现状里有几条语义是对的，重建时必须继承：

- **单调序号 + 幂等提交**：重放同一批输入不得重复生效。
- **单写者**：同一会话同时只有一个写入者。
- **持久化失败必须上抛**：绝不允许一次失败的落盘变成一次"成功"的模型或工具结果。
- **写入先于声明**：状态先持久，再标记已应用。
- **只读读取不修复、不取锁**。
- **身份经 `RuntimeContext` 传递**：禁止用 Agent 实例字段承载会话状态（`.ai-spec/backend/java.md` 硬约束）。

## 3. 目标架构

### 3.1 分层

```
agentscope-core（纯内核：无 IO、无 Spring、不依赖任何后端）
    事件日志与追加校验
    表面投影（对话节点列表）
    消息派生（模型输入）
    请求信封折取
    工具调用修复与收尾
    └── 只暴露两个动作：追加、派生
agentscope-harness / agentscope-extensions（数据面：各部件可替换）
    持久化接缝 + 本地文件后端
    投影注册表（+ 缓存）
    标题
    查询 / 检索 / 导出
    工作目录
agentscope-harness（会话编排）
    AgentSession：提交 / 引导 / 注入 / 应答 / 中断 / 继续
```

内核不依赖任何后端；后端只实现同一份日志契约；换后端不动上层。这是本次重建最重要的结构收益。

### 3.2 部件与职责

| 部件 | 职责 | 归属 |
| --- | --- | --- |
| 事件日志 | 只追加的已提交事实序列；追加时校验并冻结 | core |
| 表面投影 | 把日志折成"模型看到的那串对话节点"，支持追加与可验证替换 | core |
| 消息派生 | 把对话节点投射成消息列表，带缓存与失效 | core |
| 请求信封折取 | 折出"某次请求使用的完整信封"，支持部分窗口重建 | core |
| 修复与收尾 | 未闭合回合、无结果工具调用的补记 | core |
| 持久化接缝 | 建/开/看/列/冲刷；每会话一个读写句柄 | 接缝 + 后端 |
| 本地文件后端 | 一会话一目录一追加日志，代际文件带版本号 | harness |
| 投影注册表 | 领域注册同步纯折叠函数，宿主读当前值、界面拿快照与变更流 | harness |
| 标题 | 确定性兜底 + 可选模型提供方 + 显式改名 | harness |
| 查询与检索 | 统一查询服务 + 全文检索后端 + 规范化导出 | harness / extensions |
| 会话编排 | `AgentSession` 的全部会话操作 | harness |

### 3.3 关键不变量

以下为不可协商项，需做成类型与运行时的双重约束：

1. 追加是唯一的变更动作；已提交事件永不改写。
2. 序号连续、从零开始、等于日志长度。
3. 事件载荷必须是可无损序列化的数据；被拒绝的追加不改变日志、派生状态与事件流。
4. 事件与派生消息对外只读（不可通过持有引用篡改历史）。
5. 只有产出消息的事件族允许携带"如何进入对话"的语义；诊断类事件不得携带。
6. 未知事件类型若未显式标记为可忽略，恢复必须失败而非猜测。
7. 每个会话在同一后端实例内只有一个写入者。
8. 冲刷是唯一的耐久屏障，且全系统只有一个入口。
9. 投影折叠函数必须同步且纯粹，不关心的事件必须返回同一引用。
10. 派生结果每次返回新的容器，但内部消息对象共享。

## 4. 核心设计

### 4.1 事件分族

不再用一张平铺的大表，改为四族：

- **产出消息族**（少数几类）：系统提示、用户输入、助手回复、工具结果，外加一类供扩展使用的增量注入。只有这一族的事件决定模型看到什么。
- **生命周期族**：回合与步骤的开启和关闭、关闭原因。纯诊断，永不冒充消息。
- **诊断族**：失败的模型尝试、请求信封、路由上下文、种子边界。用于重放与排错，不进入模型输入。
- **扩展族**：压缩、审批、权限、重试、子智能体、计划、待办、标题、遥测、工作目录等，由各扩展自行注册。内核不认识这些类型。

收益：新增扩展不必改内核、不必改存储、不必动那张大表——这是现状最痛的地方。

**关闭原因**需覆盖完整结局，并区分"谁产生的"：正常完成、被取消（带取消来源）、被阻塞、出错、触顶截断、崩溃中断、分叉截断。其中**崩溃中断与分叉截断只能由恢复与分叉合成，正常运行路径永不发出**。

### 4.2 身份与顺序

- 身份：沿用 `(userId, agentId, sessionId)` 三元组，经 `RuntimeContext` 传递；持久化路径对身份段做单射转义。
- 顺序取值分三种语义（存在的事件位置 / 可等于长度的边界 / 带"尚无事件"的游标），避免现有实现里"序号与长度混用"的模糊。
- 回合 = 一次执行；步骤 = 一次模型调用 + 它请求的工具执行。用户每提交一次开一个回合，工具往返不换回合。这与会话页规格中"一条访客消息打开一个回合"直接对应。

### 4.3 表面投影：追加与可验证替换

模型输入不再来自工作副本，而是一份从日志折出的对话节点列表。

- **追加**是常规路径。
- **替换**用于压缩：记一条替换动作，遮蔽一段节点并在其位置插入新节点。被遮蔽的原文仍在日志里，界面与审计仍可读到。
- 替换需过四道校验：端点必须真实存在于当前对话；端点必须早于替换者自身；替换者必须完整声明它遮蔽了哪些节点；系统提示所在的首个节点受特殊保护，只有同样只覆盖它的系统消息才能重写。
- 先规划、后提交：校验失败不得留下部分变更。
- 缓存失效由两个世代计数驱动：一个只在替换时前进，一个在替换或扩展改写内容时前进。

### 4.4 持久化接缝

替代现有的"提交链 + 头 CAS + 写者租约 + 永久封禁"：

- 服务只提供五个动作：建、开、看、列、冲刷。每个会话发一个句柄，句柄上读、追加、冲刷、关闭。
- 追加在解决时是尽力持久；**冲刷才是耐久屏障**，并负责把空会话落实为可列举。
- 单写者由句柄占用保证；读句柄上的写入操作被运行时拒绝。
- 磁盘形态：一个会话一个目录、一个只追加的日志文件、文件名带格式版本号。已发布的历史代永不改写；要升级就在旁边发布一个新代。
- 冷启动与崩溃：未完整写入的尾部不得进入读者视野；损坏的已提交前缀按损坏拒绝，不得伪装成空日志。

### 4.5 请求信封入日志

现状完全缺失、而目标视为命门的一项。

每次请求把**与历史无关的信封**整体快照入日志：调用配置、适配器默认值、工具清单。按原因记为首次 / 恢复 / 变更 / 新序列。于是：

- 任何一轮请求都能精确重建，包括部分窗口。
- 工具清单的增删有据可查，动态增删工具不再是无痕行为。
- 会话页规格所需的上下文环构成、用量与缓存命中，从这里直接取数。

**渲染后的系统提示不放在信封里**，它是表面投影中的首个节点——否则同一份内容会有两个家。

### 4.6 派生层

- **投影注册表**：领域注册一个键、一个初始值、一个同步纯折叠函数、一个版本号；注册表只订阅一次提交事件，增量推进每个注册项。宿主读当前值，界面拿快照与变更流。所有注册项由构造保证是当前的，不存在"要不要刷新"的问题。取快照时给出对应的日志水位，让界面能把内容与历史位置配对。
- **投影缓存**：把折叠结果持久化以加速冷读。铁律是**日志领先、缓存跟随**——先确保日志落盘，再落缓存，因此缓存只会落后、绝不会超前；身份或版本不匹配即丢弃。
- **统计与回合大纲**：以"步骤结束"为步骤权威，按工具调用配对算耗时，按用量事件算令牌与速率。回合大纲给出每个回合的定位点与首条输入摘要，供界面跳转。
- **标题**：三来源新者胜——确定性兜底、可选的模型提供方、显式改名；每个被接受的修订都是一条日志事件；用户来源的标题会钉住会话不再自动修订，直到显式刷新。自动标题永不阻塞主响应，也永不进入模型输入。
- **查询 / 检索 / 导出**：统一查询服务提供精确读、关系追踪与过滤；全文检索由独立后端承担（可重建的派生索引，版本不匹配就地重置而非迁移）；导出产出规范化日志包，含被引用的二进制资源。

### 4.7 恢复与分叉

- **崩溃恢复**：折日志找出未闭合的回合与"有调用无结果"的工具，补记收尾与结果。文案按原因分叉：崩溃场景说明"结果未知，只重试只读或幂等操作，有副作用先核实"；分叉场景说明"本分支继承的历史只到此处，父会话可能在分叉后完成了它"。
- **分叉**：复制一段闭区间前缀，打一个继承标记，只关闭被截断的开放尾部；已闭合的历史原样保留，包括历史上就缺结果的调用。源会话不被改动。
- 修复属于**读者**：持久化层只返回物理有效的日志，语义修复由读取方决定是否落回。

### 4.8 会话编排（`AgentSession`）

对外操作保持现有形状不变，内在语义按新内核重新实现：

| 操作 | 语义 |
| --- | --- |
| 提交 | 先持久保存输入再安排执行；同一幂等标识重复提交得到同一回执 |
| 引导 | 关联到当前回合，在下一次推理步骤生效；已发出的请求不被改写 |
| 注入 | 只保存材料，不单独启动执行 |
| 应答 | 处理待办，并安排接续执行 |
| 中断 | 在协作检查点停止；返回不代表已经停下 |
| 继续 | 从已提交状态接着推理；不回滚工具已产生的外部效果 |
| 观察 | 等待只负责观察，取消观察不取消后台执行 |

队列语义：待处理输入仍需先落盘（页面关闭不丢），但退化为普通事件族，不再单独一套序号与"先 checkpoint 后标记已应用"的耦合。

## 5. 会话页界面复刻

### 5.1 三层分工

界面复刻不是"后端拼好页面给前端画"，也不是"前端自己解析原始日志"。分三层，各有明确归属：

| 层 | 归属 | 职责 |
| --- | --- | --- |
| 事实层 | 后端（本方案第 3、4 章） | 日志、派生消息、事件流、快照水位、用量与上下文占用 |
| 装配层 | 前端 | 事件窗口 → 会话节点的增量装配（节点身份、状态折叠、归属回合与步骤、分组） |
| 呈现层 | 前端 | 节点 → 视觉与交互（思考行、工具行、过程组、输入区） |

**装配层必须在前端**：它需要随窗口滚动、历史预取、局部结算而变化，放在后端会变成每次交互一次往返。这与第 4 章"引擎是日志的纯派生"并不矛盾——装配是**读取侧**的派生，后端只保证事实完整、顺序稳定、水位可配。

### 5.2 要复刻的呈现与交互

按已确认的 `2026-10-11-conversation-stream-design.md`，逐项对齐：

**深度思考行**（本次复刻的重点）

- 默认收起，收起时只显示一行摘要；摘要取最新一段完整文字的首行，去掉强调标记。
- 正在流出时：这一行跟随更新为最新一行非空文字，并随行尾滚动，带扫光提示；未产生完整段落时该行无摘要。
- 点开展开全文，展开后内部不再滚动，随页面一起读。
- 落定后摘要回到第一行、停在左侧；是否保留摘要预览由"显示模式"决定（紧凑模式隐藏，标准及以上显示首行）。
- 收起与展开是**逐行独立**的，不共享同一个全局开关；只有外层回合折叠时才重置。
- 中断的回合把已产出的思考前缀冻结保留，并以稳定身份落定，不因为回合中断就丢掉。
- 正文按紧凑模式渲染，段落之间不额外撑高。

**工具行**

- 同一行从发起到返回，进行中与结束是同一行的两种状态，不出现两张卡。
- 调用标识跨三个阶段稳定（参数流式生成中 → 已发起 → 已返回），保证续读时不会重复插入一行。
- 状态显示为准备中、运行中、成功、错误、已停止五态；错误、被拒、被中断各有明确显示，不伪装成成功。
- 点开看参数与返回；行内摘要、摘要后缀、正文、输出、错误摘要分层呈现。
- 结果卡片按工具名分派：命中的注册一个专属卡片，未注册或拼错落到通用卡片，坏数据也落通用卡片。
- **卡片只从日志原始记录派生**（调用名、原始参数、结果内容、错误标识、工具私有展示载荷、会话路径事实），服务端为界面准备的呈现函数**不进入浏览器**——这条约定决定了卡片所需信息必须完整落在日志里。
- 一行内可挂子调用（嵌套工具、并行调用），构成树；有深度上限与环检测。
- 文本、思考、工具参数在流式期间逐块累加；长内容按头尾截断折叠（默认约 16 行），终态摘要行不再逐字刷新。

**回合折叠（紧凑回合）**

- 回合进行时，思考、较早的助手文字、工具行、子智能体派发按产生顺序往下长，全部展开。
- 回合结束时收起成过程组：最后一步若有正文且该步无工具调用，这一步作为最终正文留在组外；最终正文之前的思考、较早回复、工具行收起。
- 收起条写三项里大于零的数：工具调用次数、最终正文之前带回复的助手消息数、子智能体派发数；三项皆零时仅表示"已思考"。
- 收起条下一条通栏分隔线，再接最终正文。
- 回合结束但没有最终正文时，过程全部保留、不收起。
- 运行中、被中断、出错的回合不可折叠。
- 常驻组外的成员固定：系统提示、用户消息、运行中补充的要求、回合触发、折叠控制本身、回合错误、触顶提示、回合尾。
- 过程组正文有高度上限，超出内部滚动；新内容到达时按需跟随，用户上滑则不抢滚动。
- 收起条文案：已结束的组按过程类目取前若干项并列（不带计数）；运行中的组显示当前类目与实时细节，类目缺失时退回"思考"，并设最小停留时间避免文案抖动。

**输入区**

- 统计条贴在输入卡片上方，含回合数、步数、已运行时长、首 token 时间、输出速率；无采样的回合不参与平均。
- 缓存命中按"缓存读入 ÷（未命中输入 + 缓存读入 + 缓存写出）"计算，输出不计入；提供方未回报缓存读入与写出时该项不出现；点开看四格明细。
- 上下文环在模型名右侧：只有同时知道"下一轮提示估算"与"模型窗口"时才出现；点开看已用百分比、用量与容量、以及系统提示/工具/消息三行构成，并明确标注为估算。
- 模型位显示当前模型，可切换；运行中文本框不可输入，模型位仍可点。
- 统计口径按整段会话累计，不随对话区滚动加载而变少。

**其他节点**

- 用户消息、系统提示、上下文注入（含运行中补充的要求）、命令与手动压缩、模型重试、回合错误、触顶提示，各成一类节点。
- 子智能体：主会话里的派发行就是普通工具行（类目归到子智能体）；点开后是**子会话自己的完整时间线**，复用同一套装配与呈现，只有外壳与只读输入区是子智能体专属；一次性任务只读。
- 锚点：每个可定位的节点带稳定锚点，时间线用锚点跳转；目标在收起的过程组内时先展开该组再跳。

### 5.3 流式与续读（与第 4 章的交界）

这是复刻里最容易做浅的一块，也是本次必须做对的一块。DSH 的客户端可见模型是：**durable 与 transient 两种条目汇入同一个事件窗口**，并且有明确的增量操作，而不是"每次通知就重折全部"。

- **窗口变更只有四种**：整窗重建、尾部追加、历史前插、**尝试结算**。
- **结算**是关键操作：一次模型尝试结束时，先移除该尝试的全部临时条目，再在其位置插入 durable 结果；装配器只退役这一个尝试的临时节点并重算受影响的部分，**未受影响的节点身份与已发布内容不变**。
- 结算时是**用 durable 助手消息的内容块整体替换流式累加结果**，原始流在界面上不保留。因此"思考与工具调用是助手消息里的一等内容块"是硬要求：只把思考存成附加文本、或只存最终答复，都会导致刷新后思考行无法还原。
- 流式期间按块累加并按动画帧节奏对外发布（用量与结束信号则立即发布），避免每个增量都触发一次渲染。
- **前插（向上翻历史）不得改变已有节点的身份**，否则已渲染内容会跳动或重复。
- 临时条目按尝试归属，**不按序号与 durable 混排**，否则结算时无法定位要退役哪些。
- 快照与续读必须成套：先取某个水位的完整快照（含**完整的已有内容**，而不只是最终文本），再从该水位续读增量。只存一个续读游标、不取快照，刷新后就会缺内容。

与之相配，后端需在快照里给出足够的事实：助手消息在日志中**自带思考内容块**（不是只带最终答复文本）、每个工具调用的稳定标识与三阶段时刻、用量与上下文占用、以及回合与步骤的归属。第一项是"深度思考刷新后能完整还原"的前提——现有实现只在回放时取思考的最终全文，等于把思考的展示能力砍掉了。

### 5.4 与现有前端的差距

现有会话页已有相当基础（`conversationModel.ts` 的投影函数、`useAdvisorConversation` 的流处理、`processCards`/`ThinkingCard`/`ComposerDock` 等组件，合计约 4900 行），下列差距需要在本次补齐：

| # | 差距 | 性质 |
| --- | --- | --- |
| G1 | 思考在日志与快照中不是一等内容块，只作为附加文本落库 | 事实层缺陷，必须修 |
| G2 | 装配是"重折整个窗口"，无增量追加、前插与尝试结算 | 结构性缺陷，导致流式逐行与稳定身份都做不到 |
| G3 | 工具行缺稳定标识与三阶段时刻配对，续读可能重复插入 | 事实层缺陷 |
| G4 | 回合折叠与过程组是逐条消息的卡片序列，不是"一个回合一次折叠" | 呈现结构差异 |
| G5 | 输入区的上下文环与缓存命中只有数据半成品，无三行构成与四格明细 | 事实层 + 呈现 |
| G6 | 子智能体只有列表与卡片，没有可点开的子会话时间线 | 能力缺失 |
| G7 | 统计口径部分依赖应用自有表，未从日志派生 | 与第 4 章投影层重复建设 |

### 5.5 复刻边界

**照做**：信息架构、交互方式、状态机（收起/展开、进行中/落定、工具行五态、过程组折叠）、视觉排版与层级、文案口径、空态与异常态、长内容的头尾截断与过程组高度上限。

**替换**：技术栈与组件实现按本仓库既有前端规范重写，不引入 DSH 的插件槽与注册表容器、样式 token 体系、i18n 注册机制与图标库；工具名到过程类目的映射表按本仓库工具集重新定义。

**不做**：DSH 的会话日志设置页、三车道轨迹图、配额与账号通知链、品牌动效与品牌图标、桌面端专属行为。

**子智能体**照"复用同一套时间线"的做法实现，不另建一套渲染器。

**长会话**需自行处理：DSH 的对话区不做虚拟化（靠过程组高度上限与卡片头尾截断控制体量），本仓库若需支撑很长的会话，应在保持节点身份稳定与语义锚点的前提下自行补虚拟化；这一点不能等界面做完再补，否则锚点跳转与滚动补偿都要返工。

### 5.6 数据流形态取舍

传输层保持现状：现有前端经 AG-UI 协议（`text-delta`、`reasoning-delta`、`tool-args`、`token-usage` 等信号）取流，鉴权、路由与重连机制都建在其上。本次**不改传输协议**，而是把流内承载的内容换成新契约（回合与步骤边界、稳定的工具调用标识、思考内容块、用量与上下文占用），并保留原有的文本与思考增量信号作为流式通道。

新增两条必要能力：一是**按水位取完整快照**的读取接口（现有接口只提供列表与逐条消息）；二是**临时条目的尝试归属**（在流内标注本次尝试，使前端能在结算时精确退役对应的临时节点）。

### 5.7 验收

- 视觉对照：与 DSH 同场景截图逐项比对（思考行收起/展开/流式中、工具行五态、过程组收起与展开、输入区统计与上下文环）。
- 回放：刷新页面后，思考行、工具行、过程组、用量与缓存命中全部还原，且思考行能按其既有内容完整呈现。
- 流式：思考与工具参数逐行更新；一次尝试结算时未受影响的节点不重建、不跳动。
- 交互：过程组展开后跳转到组内目标；子智能体点开后可返回并保持列表滚动位置。
- 数据一致性：界面显示的工具调用次数、步数、耗时与统计条一致；同一会话在两条读取路径上结果一致。

## 8. 落地安排

### 8.1 为什么不拆细

原先设想的八阶段被压成三段。八段的浪费在于：真正卡住别人的只有内核接口，而每多切一段，接口就绪就更晚；且本地文件后端是多数阶段的地基，拆细等于把一条串行链从头拉到底。三条真实依赖只有：**内核 → 数据面 → 切换**。

界面复刻也按同一原则处理：**数据契约定在阶段 A**（第 5.3 节列出的事实清单），**装配层与呈现层在阶段 B 动工**，与后端的读面并行；**阶段 C 一次切换**。界面不单独再切一个阶段——它的返工风险来自契约定晚了，而不是来自工作量大。

### 8.2 三个阶段

| 阶段 | 范围 | 验收标准 | 并行性 |
| --- | --- | --- | --- |
| **A 内核与耐久底座** | 日志与追加校验、表面投影、消息派生、请求信封折取、修复与收尾、分叉；本地文件后端与句柄契约测试；**会话页所需事实清单定稿** | 内核契约测试与后端契约测试全绿；能用新内核把一段真实历史日志折出与今天逐条一致的消息列表 | 完成后接口与前端契约同时冻结；B 可与之并行启动 |
| **B 全部读面与扩展** | 投影注册表与缓存、统计、回合大纲、标题、查询/检索/导出、工作目录；**前端装配层与呈现层重做** | 同一份日志折出的界面快照与统计逐项对齐；第 5.7 节的界面验收在桩数据下先行通过 | 内部各部件互不依赖，可并行；前端可在后端未切换时用桩数据推进 |
| **C 一次性切换** | `AgentSession` 与 Agent 接线、前台接真数据、删除旧实现 | 全量构建与测试通过；崩溃、分叉、中断续做端到端通过；界面验收在真数据下复验；文档 EN/ZH 同步 | 唯一不可回滚点 |

### 8.3 各阶段要点

**阶段 A** 是唯一的重活，风险是"迟迟没有整体验收"。对策不是再切阶段，而是 A 内部按六个领域各带自己的单元测试，谁测完谁算完成，不必等 A 整体收口：

1. 追加不变量（连续性、拒绝后状态不变、载荷可无损序列化）
2. 替换四道校验与遮蔽完整性
3. 消息派生与缓存失效
4. 请求信封折取（含工具清单增删）
5. 修复与收尾（未闭合回合、无结果调用）
6. 分叉切点与继承边界

A 收口时必须交付的界面契约（第 5.3 节）：助手消息含思考内容块、工具的稳定标识与三阶段事实、用量与上下文占用、回合与步骤归属、按水位的完整快照、临时条目的尝试归属。这份清单冻结得越早，阶段 B 的前端返工越少。

**阶段 B** 全部依赖"能按水位读日志"这一件事，因此与 A 的接口冻结即可并行推进。前端在此阶段用桩数据把装配层与呈现层做完并自测通过，避免界面工作被后端进度绑定。

**阶段 C** 是唯一的切换点，此前新旧并存：旧实现继续服务 `AgentSession`，新实现以新增方式落地。切换后旧实现保留到验证全绿才删除。

### 8.4 回滚

- 阶段 A、B 期间随时可停：旧实现未动，新实现是增量；前端可继续用旧数据源。
- 阶段 C 之后回滚 = 恢复被删除的旧实现文件，并从旧日志格式重新开始（已声明不兼容旧日志，因此不存在数据回填问题）。前端装配层因已按新契约重写，需与新实现一并回滚。
- 阶段 C 建议在单次提交内完成"接线 + 删除旧实现 + 文档同步"，避免出现两套并存的中间态。
