# 动态上下文容量实施计划

**目标**：输入区使用 K/M 显示剩余 token；每轮使用当前启用模型的真实窗口，支持 1M 或更大窗口，但不将所有模型固定为 1M。

**能力来源顺序**：已配置接入端 GET /models 的当前模型 context_window → 现有 SDK 模型能力目录 → 未知时保持保守预算。配置文件仅是没有已保存当前模型时的回退来源。

## 范围

- 前端 lib/format 与 ComposerDock：格式化剩余/已用/总量，保留悬停/点击详情与阈值。
- 应用 ModelCatalog 和幂等 AdvisorSchema：保存接入端确认的窗口，不存入用户会话内容。
- OpenAiEndpointClient 与 ModelProbe：获取当前模型的能力；后台保存/启用模型或管理员模型列表初始化时刷新，不在模型生成事件循环中阻塞读取网络。
- SavedChatModelSource：每次取实际 current endpoint 的窗口构建模型。仍用既有 token_usage.contextWindow 传至前端；GET /api/advisor/models 的模型项补充可选 contextWindow，让切换模型后、尚未产生新采样时也使用当前模型的上限。旧客户端忽略该可选字段。
- 既有压缩逻辑按实际窗口减预留空间触发。检查应用是否被固定消息数提前压缩；保留模型输出与压缩所需预算。

- [x] 本地模拟模型能力接口：接入端窗口优先于 SDK 默认值，不同模型返回不同窗口，不认识的模型不伪造 1M。
- [x] 验证容量落库、当前模型使用容量、重启后读取容量。
- [x] 前端门禁、聚焦后端测试及格式检查。不要向真实模型发百万 token 测试，不启动浏览器。

## 审查修正

- 未知能力返回0，安全预算留给harness fallback，界面不伪造32K。
- 新增无共享状态的SelectedModelMiddleware，冻结每次模型调用的选择；预算/生成/用量事件使用同一模型快照。
- 窗口样本仅沿用最新模型的连续区间；不读取无权限用户的旧管理目录缓存。
- 不自动重启现有后端，不发真实长上下文请求；加列与启动能力发现将在后端重启时执行。
