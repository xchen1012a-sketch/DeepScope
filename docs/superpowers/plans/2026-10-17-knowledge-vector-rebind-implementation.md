# 知识库手动换模型与重建实施计划

执行已批准的 `../specs/2026-10-17-knowledge-vector-rebind-design.md`，保持原地重建，无影子表或新依赖。项目已迁移为 deepscope-app / io.deepscope，保留所有重命名及并行改动。

## 契约与落地细节

- `POST /api/advisor/knowledge/{libraryId}/reindex`，请求仅 embeddingEndpointId；复用库编辑/管理权限。202返回 affectedDocuments/embeddingEndpointId/embeddingDimensions/rebuilding；无效端点400、忙库409，空库直接绑定。相同模型无变化时不清索引。
- 新增库内 `GET .../{libraryId}/embedding-models`，只返回端点ID、显示名、维度及系统默认标记，不要求额外模型管理权限、不返回URL或凭据。列表响应新增 documentCount/rebuilding，兼容旧字段。
- 持久库状态区分ready/rebuilding；整个库所有文档完成前均暂停检索，失败/重启仍保留暂停状态，允许复用现有单篇重新处理恢复。上传在重建期间返回409，避免新增文档插入索引重置窗口。
- 统一库→文档加锁顺序。短事务内校验无活动文档，更新绑定及维度、清向量checkpoint、重置文档状态、DROP旧向量表；PostgreSQL事务回滚须保留旧绑定/旧表。框架store缓存按表及维度区分并清理，避免旧维度实例复用。文档原文、已发布文字切片和页面来源不删除。
- 重建锁定目标模型期间，删除模型也必须先锁同一端点再检查引用，避免引用校验先通过、等待重建提交后却删除新绑定端点。此竞态已在真实PG定向复现，沿既有删除校验补事务边界。
- 异步重建优先复用已保存文字切片及来源，缺失才回退源文件；无需重传或再次OCR已完成内容。队列按容量分批投递，超过原队列容量的文档不能被误判失败。服务关闭/重启未完成文档标中断，可通过现有重新处理恢复。
- 重建失败不得因旧结构切片存在而误标ready；最后一篇成功、或删除失败文档使剩余均ready时，事务内解除全库检索暂停。检索返回前复核库绑定/重建状态，避免切换期间返回旧空间结果。
- 前端在现有设置中提供独立模型选择及“保存模型”，不混改尚未保存的分块参数；有文档弹出危险操作二次确认，取消不变。成功切换到文档Tab，展示重建暂停提示及现有进度。只读用户不能修改。

## 验证顺序

先RED：空库切换API、错误类型/越权；然后服务级同维度/异维度、忙库冲突、失败状态/全库检索暂停、切片重用和超过队列容量、物理表维度及事务回滚、重启后重试。前端选择/取消/确认/空库/只读/409。复用独立PG测试实例，不重跑真实文档、不起浏览器。最后按受影响模块门禁运行并记录实际失败，不重置混合工作区，不提交推送。
