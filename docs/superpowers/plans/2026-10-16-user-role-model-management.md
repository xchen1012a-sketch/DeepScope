# 模型、用户与角色管理技术实现方案

日期：2026-10-16。状态：已实施；验证记录见 `technical-advisor-app/docs/user-role-model-management-results-2026-10-16.md`。

### 实施补充（用户确认与截图校正）

- 用户与角色界面以用户提供的芋道截图为准：独立紧凑搜索卡片、标签横排、列表工具栏放新建按钮，操作为编辑/删除/更多文字。复用现有组件的变体，不改变工具/MCP等页面默认样式。
- 用户标识文案为“账号”，角色对应字段为“角色标识”。只展示本项目真实已有字段，不补造部门、手机、导入导出或数据权限功能。
- 更多菜单提供用户分配角色、重置密码及启停，角色提供授权及启停。分配角色、重置密码使用独立受保护接口。
- 内置 admin 账号与内置角色均不可停用；后端存储约束与前端禁用共同保护。现有最后一个超级管理员保护保留。
- 权限树补充实际页面操作叶子，旧 manage 权限继续涵盖本模块操作；新增操作权限不赋予跨用户资源管理能力。用户角色分配需 role.grant，内置/超级管理员资料及密码操作仍需 rbac.manage。
- 模型复制配置通过 no-store 响应，仅在复制函数内暂存密钥，不使用 Query/Mutation 缓存。沿用模型配置的系统级管理范围，数据库没有模型账号归属字段，不虚构归属校验。
- 地址或认证协议改变后必须重新输入密钥，避免测试/发现接口把已存密钥传往新地址。
- 向量服务商仅补充官方文档可核实的预设；发现结果使用已核实向量 ID 或返回的明确向量能力，未分类 ID 不出现在候选列表，允许手填后以向量探测验证。

## 目标与边界

本次同时优化三类管理能力：模型设置、用户管理、角色管理及授权树。

明确边界：

- 用户管理列表不增加“接入模型”字段。
- 角色管理列表不增加“接入模型”字段。
- 用户和角色搜索卡片不增加“接入模型”筛选条件。
- “接入模型”只属于模型设置页面，用于模型连接、模型发现和向量模型能力控制。
- 复用现有 `DataTable`、`TableToolbar`、`Pagination`、`AppSelect`、`Dialog` 和 `usePagedList`，不新建第二套列表框架。

## 一、模型设置

### 1. 完整复制配置

当前模型列表只返回密钥掩码，前端不能直接复制真实密钥。新增管理员保护接口：

```http
POST /api/advisor/models/{endpointId}/copy-config
```

返回一次性配置对象：

```json
{
  "provider": "openai",
  "providerName": "DeepSeek",
  "baseUrl": "https://api.deepseek.com/v1",
  "modelName": "deepseek-chat",
  "secret": "真实密钥"
}
```

实现规则：

- 只允许模型管理权限调用，并检查当前账号归属。
- 不写日志、不写缓存、不修改数据库。
- 前端点击“复制配置”后生成 JSON 文本写入剪贴板。
- 成功后显示短暂提示，页面不展示完整密钥。
- 复制失败显示重试提示，不回显密钥。
- 测试中不使用真实密钥，增加授权、响应不落日志和复制失败测试。

### 2. 向量模型服务商与模型 ID

供应商接口继续使用 `kind`：

```http
GET /api/advisor/models/providers?kind=embedding&q=&limit=30
```

后端只返回 `embedding` 能力明确支持的预设。前端不得用聊天供应商列表过滤代替后端能力判断。

模型 ID 接口必须携带 `kind=embedding`，包括：

- 内置预设建议。
- 主动“获取模型”发现结果。
- 发现缓存。
- 分页搜索。

服务端在缓存查询和保存前再次校验 `kind`，防止聊天模型 ID 进入向量模型列表。保存前使用向量探测接口验证响应维度，Anthropic 等未提供向量能力的供应商不得出现在向量服务商下拉框。

### 3. 配置复制入口

列表操作增加“复制配置”，放在配置、测试等常用操作中；低频操作进入更多菜单。复制是敏感操作，使用明确的文案和短暂反馈，不使用图标代替说明。

## 二、用户管理

### 1. 搜索卡片布局

按钮和搜索条件放在同一个卡片内：

```text
┌──────────────────────────────────────────────┐
│ 用户名                                        │
│ [搜索用户名                  ]                │
│                                              │
│ 角色                                          │
│ [全部                      ▾]                │
│                                              │
│ [查询] [清除]                    [新建用户]  │
└──────────────────────────────────────────────┘
```

统一规则：

- 所有标签放在输入框上方。
- 输入和筛选都是草稿状态，点击“查询”才请求后端。
- “清除”使用 `AppSelect.allowClear` 和统一清除能力，清空草稿、筛选和分页。
- 筛选默认值为空，显示“全部”。
- 不显示、不筛选“接入模型”。用户接入了哪个模型不是用户管理列表的管理维度。

### 2. 后端查询

沿用现有分页接口：

```http
GET /api/advisor/users?page=1&size=10&q=alice&status=active&roleId=role-id
```

用户列表保留 `q`、状态和角色筛选。状态筛选仍表达账号状态，不改名为“接入模型”。所有参数由 `JdbcPage` 参数化查询，错误不能返回空列表伪装成功。

### 3. 列表字段与操作

列表字段：

```text
用户名 | 昵称 | 角色 | 状态 | 备注 | 创建时间 | 操作
```

- 状态使用 `Badge`，区分启用/禁用，不用可点击文字伪装标签。
- 内置账号保留内置标记。
- 操作：编辑、启用/禁用、删除。
- 删除使用危险确认；内置账号和最后一个超级管理员不可删除。
- 禁用最后一个超级管理员由后端继续拒绝。
- 操作列复用 `DataTable.actions` 和 `TableActions`，编辑保持纯文字。

## 三、角色管理

### 1. 搜索卡片与后端查询

沿用同一张搜索卡片结构：

```text
角色名          编码          状态
[输入框]        [输入框]      [全部]

[查询] [清除]                    [新建角色]
```

接口：

```http
GET /api/advisor/roles?page=1&size=10&q=admin&code=ops&status=active
```

角色筛选只包含名称、编码和账号状态，不包含“接入模型”。选择筛选项不会即时请求。

### 2. 列表字段与操作

移除“人数”字段，改为：

```text
角色名 | 编码 | 描述 | 状态 | 创建时间 | 操作
```

操作：

- 编辑：纯文字。
- 授权：使用权限图标配“授权”文案，图标语义和动作一致。
- 启用/禁用：内置角色不可切换。
- 删除：危险图标操作，内置角色和被保护角色由后端拒绝。

角色查询返回描述、创建时间和权限摘要，前端不自行计算人数或权限状态。

## 四、通用服务商选择器

将模型设置中的服务商搜索抽成通用组件：

```text
ServerProviderSelect
```

组件能力：

- 通过 `/api/advisor/models/providers` 后端搜索。
- 接收 `kind=chat|embedding`。
- 支持全部、清除、加载、错误、空结果和已选回显。
- 不在前端保存全量供应商数组。
- 支持键盘、焦点和取消请求。
- 供应商预设只负责地址和协议建议，保存与测试仍由后端实际校验。

应用范围：模型设置、模型筛选和后续所有需要选择服务商的页面。用户/角色页没有服务商字段，不强行接入该组件。

## 五、树形授权

### 1. 当前问题

现有角色授权使用扁平 `PERMISSIONS` 数组，角色页直接维护权限码列表，无法表达“页面 → 按钮操作”的层级。

### 2. 后端权限树

新增只读接口：

```http
GET /api/advisor/permissions/tree
```

返回目录节点和叶子操作：

```json
[
  {
    "id": "agent",
    "name": "智能体管理",
    "children": [
      { "id": "agent.view", "name": "查看", "children": [] },
      { "id": "agent.edit", "name": "编辑", "children": [] },
      { "id": "agent.delete", "name": "删除", "children": [] }
    ]
  }
]
```

权限树来源统一维护在后端 `AccessPoints`，前端不再复制一份固定权限常量。

现有接口保持兼容：

```http
GET /api/advisor/roles/{roleId}/permissions
PUT /api/advisor/roles/{roleId}/permissions
```

保存请求只提交叶子权限 ID：

```json
{ "permissions": ["agent.view", "agent.edit", "model.test"] }
```

后端校验所有 ID 必须来自权限树，未知权限拒绝保存；内置角色按既有规则只读。

### 3. 前端授权树

授权弹窗改为树形结构：

- 页面节点可全选或取消全部子操作。
- 子操作部分选中时，页面节点显示半选。
- 页面节点下列出具体按钮操作，如查看、创建、编辑、删除、授权、测试。
- 打开弹窗先请求权限树和角色当前权限。
- 保存提交叶子权限。
- 保存失败保留当前勾选状态。
- 关闭后重新打开以服务端数据为准，不依赖旧本地状态。
- 内置角色显示只读树，不出现保存按钮。

## 六、文件与实施阶段

### 阶段一：模型配置与通用服务商

- 后端新增模型配置复制接口和权限测试。
- 完善向量服务商能力及向量模型发现过滤。
- 抽取 `ServerProviderSelect`，替换模型设置中的服务商选择。
- 前端补复制、向量、失败反馈和密钥安全测试。

### 阶段二：用户与角色列表

- 复用 `TableToolbar`，统一搜索卡片标签位置。
- 将新建按钮移入搜索卡片底部。
- 用户和角色所有查询改为点击提交后后端查询。
- 状态标签、字段、操作和确认反馈统一。
- 不添加“接入模型”字段或筛选。

### 阶段三：权限树

- 后端提供权限树投影和叶子权限校验。
- 前端新增通用 `PermissionTree`，接入角色授权弹窗。
- 覆盖半选、全选、保存失败、内置角色只读和未知权限拒绝。

### 阶段四：验证与文档

- 后端运行模型、访问控制和权限树行为测试及 Spotless。
- 前端运行相关访问页、设置页测试、全量测试、Lint 和 Build。
- 同步中英文模型设置、用户管理、角色授权说明。
- 不启动浏览器，除非组件行为无法由单元/集成测试证明。

## 七、关键验收标准

- 用户和角色列表完全没有“接入模型”字段和筛选。
- 用户/角色搜索输入不会实时请求，点击查询才发送后端请求。
- 新建按钮位于搜索卡片底部，清除后恢复空筛选和第一页。
- 用户、角色字段和操作完整，状态使用标签，危险操作有确认。
- 角色授权呈页面树和按钮叶子节点，支持半选和服务端保存。
- 向量模型只展示向量服务商和向量 ID。
- 复制模型配置受权限保护，密钥不写日志、不落前端状态。
- 所有新增行为有测试证据，未验证的真实厂商和视觉观感不作通过结论。
