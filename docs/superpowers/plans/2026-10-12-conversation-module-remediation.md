## 阶段一：搜索止血（一个提交）

**闭环目标**：任何一次会话搜索的返回体积有硬上限；超大工具结果自动落盘；豁免不再保护可能大的工具。

**要点**：

- [ ] `SessionSearchTool` 粗检索重写：命中只返回片段（二百四十字符左右、命中点约前三分之一居中、两端省略号）+ 坐标（会话号、事件序号、所在智能体）；默认范围限当前智能体、排除当前会话，跨范围须显式传参；条数上限即体积上限（默认一百条，触顶提示收窄查询）；每会话只回最佳匹配一条
- [ ] 新增精读工具（如 `session_read`）：按会话号 + 事件序号取前后邻域窗口原文，单次上限五十条——模型需要全文时二次调用
- [ ] 输出改纯文本行，消灭 JSON 套 JSON
- [ ] 豁免名单清理：`ToolResultEvictionConfig.DEFAULT_EXCLUDED_TOOLS` 与 `CompactionConfig.PruneConfig` 默认名单移除 `session_search`——既有落盘机制（八万字符阈值）自动接管超大的搜索结果
- [ ] 豁免原则收敛：名单只留 `read_file`/`write_file`/`edit_file`/`memory_search`/`memory_get` 这类天生小或自带分页的工具

**验收**：定向测试——不传范围时只搜当前智能体且排除当前会话；命中返回片段含坐标；精读工具按坐标取回原文；`session_search` 产生的兆级结果被落盘机制替换为头尾摘要。阶段门禁一次通过。

**参照**：`deepseek-harness/packages/session-query/src/query.ts`（makeSnippet 的居中与省略规则）、`packages/experimental/tool-session-query`（工具参数与提示文案）。

## 阶段二：预算口径与状态收口（一个提交）

**闭环目标**：预算数字一处说了算、压缩先于报错；中文报错同样触发恢复；会话不再永久卡「运行中」。

**要点**：

- [ ] 预算口径统一：兜底上限（现 64000）与压缩触发线（现 160000）的矛盾消除——兜底改为与压缩线联动（压缩线取兜底的八成），保证压缩永远先于报错
- [ ] 字符换算比例统一为单一常量来源（现 2.5 与 4 两处并存）
- [ ] 超限恢复识别按错误类型而非英文文案子串，中文报错同样触发强制压缩重试
- [ ] 会话状态机补「中断」终态：任何退出路径（正常/报错/中断/超时）都落到终态，消灭永久「运行中」（advisor 应用层）

**验收**：定向测试——压缩线恒小于报错线；中文错误消息触发恢复路径；中断后会话状态为终态。阶段门禁一次通过。

## 阶段三：服务端即写（一个提交）

**闭环目标**：对话内容（正文、思考流、工具调用）在服务端产生时就落库，落库职责与前端回传彻底解耦——刷新、切换会话、断网中断都不丢已产生的内容。

**要点**：

- [ ] 落库时机前移：正文/思考流/工具调用事件改为服务端产生时写入时间线（沿用既有时间线存储，只改写入时机与入口），前端回传通道保留用于展示确认，不再作为持久化前提
- [ ] 中断兜底：一轮回答被中断（断连、停止、异常）时，已产生的增量内容在服务端收口落库，配合阶段二的终态化，会话重进后内容完整且状态正确
- [ ] 不做语义检查点、不做检查点失败阻断（远期参考）——最小版只保证「产生即写」

**验收**：定向测试——回答中途断开，已产生的正文/思考流片段完整在库；重进会话回放内容与状态一致；正常路径落库内容与改造前等价（不重复、不丢条）。端到端人工验收：正常对话、中途刷新、中途断网三场景。阶段门禁一次通过。
