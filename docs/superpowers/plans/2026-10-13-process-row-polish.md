# 思考与工具过程行：技术实现方案

**目标**：统一思考行、工具行与工具组的视觉状态，保留现有展开能力，并控制长内容渲染与计时资源。

**确认范围**：用户已确认视觉调整，同时确认长日志分页和计时器改造有必要。这是本次唯一实施方案，后续进度直接更新本文，不另起版本。

**当前状态**：已完成实施与验收。前端全量235项测试通过，构建通过，lint零错误（保留现有25项警告）。下列清单已按实际验证结果完成。

## 1. 最终呈现与交互

| 状态 | 思考行 / 工具行 | 工具组标题 |
| --- | --- | --- |
| 运行中 | 左侧紫色加载环，动作与对象摘要，工具耗时淡色展示 | 折叠时加载环；展开时标题保持静态，具体行显示实际状态 |
| 完成 | 左侧静态细线图标，保留摘要和已有耗时 | 静态图标与完成摘要 |
| 失败 | 左侧红色提示图标，简短原因直接可见 | 失败提示与简短原因 |

- 去掉`>`箭头、工具名厚重徽章和状态胶囊，减少边框，统一图标大小、字号和间距。
- 整行仍是原生button；保留键盘操作、可见焦点与aria-expanded。没有参数/结果的工具不提供无内容的展开操作。
- 已知工具使用EN/ZH动作名；未知工具保留原始名称，原始工具名也保留在提示中。不调用模型生成显示名称。
- 手动展开不因流式更新或任务结束而重置；沿用既有稳定ID和时间线定位能力。
- 空思考不绘制，关闭Think的本轮不显示思考，已保存的真实思考保留。这些已完成的行为不能回退。

## 2. 动效和长内容处理

### 动效

复用Tailwind和lucide-react，通过CSS transform旋转实现加载环；完成立即切换静态图标。遵守prefers-reduced-motion，不新增动画库、JS帧循环或动画定时器，也不创建外部图片资源或Blob URL。

### 分页

长参数、工具输出和思考正文仅在展开后挂载。每页约12000个字符，点击上一段/下一段查看完整内容；短内容直接完整显示。这里只限制当前DOM中的文字量，不修改或截断已保存的内容。

分页用本地页码state和字符串slice；不把长文本一次性拆成全部页面数组，不做整篇Markdown或语法高亮解析。流式更新保留用户当前页；内容变短时页码保持有效。

### 摘要与计时

- 思考摘要只扫描头部或尾部有限长度的文字，不随每个token重扫全文。
- 参数摘要设置解析大小上限，半截JSON不反复解析；复用已有useMemo。完整参数仍能在展开后按页查看。
- 继续复用useNowTicker的一秒计时，页面隐藏时暂停，恢复后按当前时间更新；任务结束和组件卸载时清理interval与visibilitychange监听。
- 展开工具组才挂载具体行；收起后的行释放计时资源。计时与CSS动画各自独立。

### 问题与参考

当前ThinkingLine有固定中文状态前缀；ToolLine以统一动作名和一个通用参数预览呈现；InlineProcessGroup在多工具完成时默认全部收起，仅显示“已使用N个工具”。因此完成态缺少可直接阅读的实际操作记录。

Claude公开帮助说明会在聊天中显示搜索工具调用；Codex公开App Server协议将reasoning、commandExecution、fileChange等作为独立过程项，命令项包括命令、工作目录、状态、输出、退出码和耗时。参考其“实际操作可见、过程按位置记录”的方向，下面是适配本应用的设计，不声称复制当前产品的全部视觉细节。

参考：
- https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context
- https://learn.chatgpt.com/docs/app-server

### 呈现与交互

1. 思考运行中保留紫色加载环和英文`Thinking`前缀，后面沿用现有摘要。完成后停止加载、切换轻量静态图标，直接展示现有摘要，不再附加“思考/已思考”中文前缀。真实思考有正文但无可用摘要时显示`Thought`；空思考、Think关闭行为保持不变。点击整行仍可展开原有分页正文，不推算不存在的思考耗时。
2. 工具行改为“实际动作＋对象”。读取展示路径，命令展示真实command（而非随意挑第一个参数），检索展示关键词和范围，网页展示域名/链接，编辑展示目标文件，派发展示目标智能体。运行文案例如“正在运行 npm test”；完成例如“已运行 npm test”；失败例如“运行 npm test 失败”，简短原因直接可见。耗时位于右侧，参数和原始输出仍按需展开。
3. 每段连续工具按实际位置和顺序显示；完成后默认保留前三条轻量操作行。超过三条时显示“查看其余N项 · 读取X次 / 执行Y次…”的展开入口，统计来自其余真实调用，而非模型推测。失败项即使在默认隐藏部分也需可见，并从隐藏计数中扣除；展示顺序保持原顺序。不再只用“已使用N个工具”概括所有动作。用户手动展开/收起优先，已有展开不因完成而重置；执行时间线定位时照常自动展开并定位。
4. 维持13px、淡灰/紫色、统一图标与行高；不增加卡片、分隔横线或成功胶囊，不恢复`>`箭头。这里只将思考状态前缀改为英文，其余操作句跟随界面语言。

### 实现边界

- 在chat feature内增加纯展示函数（如toolPresentation.ts），由真实工具名、参数、status生成动作类型和目标；ToolLine与工具组统计共用同一映射，替代重复与通用PREVIEW_KEYS推断。
- 未知/MCP工具保留实际工具名与可识别的目标，不把未知操作错误翻译为读取或修改。先覆盖项目实际注册的工具名，再用既有回退。
- 只根据真实调用记录描述“做了什么”；不从思考文本虚构执行记录，不额外调用模型生成总结，也不把命令结束描述为“测试通过”。可识别结果才显示结果信息，缺失时不猜。
- 复用现有ToolCall与ordered blocks；主要改ThinkingLine、ToolLine、TurnGroup和EN/ZH词典，不改变事件、持久化结构、后端或路由。旧聚合记录继续原有兼容展示，无法恢复的历史位置不推测。
- 保留已完成的CSS动效、减少动态效果、分页与计时清理。默认展示行数有限，折叠的其余行不挂载；参数解析仍设大小上限，仅参数变化时计算，不扫描整段输出。
