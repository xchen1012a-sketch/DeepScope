目标：权限回归、前端门禁、真实契约和 F08 实际使用闭环。
技术栈与边界：Spring Boot / JDBC / PostgreSQL；React / Radix / TanStack Query。仅修改 technical-advisor-app，复用框架解析、工具清单与每轮子智能体重载机制，不改框架。
依据：docs/superpowers/HANDOFF-2026-10-10.md；docs/superpowers/specs/2026-10-09-technical-advisor-tds.md 阶段四。

1. 修复更新权限：已存在资源先检查编辑权，拒绝返回 403；读和删除保持可见性过滤。运行既有回归，再执行根目录 mvn -T1 -pl technical-advisor-app/backend -am test。
2. 审查前端当前分步创建、复制与按需加载实现。运行 frontend 的 npm run build、npm run test、npm run lint；不重做界面。
3. 真实契约补齐：后端返回当前用户编辑权、实际工作区章节与数量；前端读取现有数组列表。新建复制仅从可见源复制工作区，不复制会话状态。工作区文件接口复用 AgentSpecLoader 校验子智能体定义，并拒绝路径穿越和符号链接。
4. 自由模式每轮路由：读取本轮问题，严格解析模型选择，失败回退内置智能体；追加 agent_route 时间线，保持未绑定。锁定模式不调用模型。回归覆盖两轮分别路由、异常回退和锁定不调用模型。
5. F08：工具禁止自由会话提案；裁决检查会话属主、智能体编辑权和最早同名待处理提案。批准以修改后的定义创建唯一文件，再写裁决记录；重复裁决冲突，不覆盖已有定义。拒绝只写裁决。复用时间线和框架热加载，不新增派发运行时。测试覆盖权限、FIFO、修改草稿、拒绝、重复与无效定义。
6. 更新阶段四使用说明 EN/ZH。针对新增逻辑先运行行为回归确认失败，再最小实现；最后运行受影响前后端门禁与格式检查。
7. 后端用本地私密模型配置与 ADVISOR_DATABASE_USERNAME=juvon 启动。真实新建、复制、路由各一次；F08 模型提案、批准、新子智能体下一轮派发且产生实际结果。浏览器仅在实际前端批准验收时使用一次。
