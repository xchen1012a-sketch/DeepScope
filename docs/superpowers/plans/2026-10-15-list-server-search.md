# 列表搜索链路修正

用户发现点击搜索不发送请求，确认原因是此前仅把前端filter改为手动触发，接口从未接收关键词。本次按用户要求修复，不启动浏览器。

## 契约和范围

- 保持现有GET路由与数组/对象响应兼容，新增可选 q 关键词。无q返回原权限范围列表；有q在数据库对名称/描述等公开搜索字段执行参数化、不区分大小写的字面子串匹配，%/_不作为通配符；权限条件整体括号后与搜索条件AND，防止管理/所有权OR条件绕过筛选。
- 路由：/api/advisor/agents、/agent-creation-drafts、/skills、/knowledge、/tools、/mcp-servers、/models、/users、/roles。
- 用户进一步明确：所有管理列表必须服务端分页与筛选。统一 `page`（1起）、`size`（默认10、最大100）、`q`；响应为 `items/page/size/total/totalPages`，参数不合法返回400。SQL执行 COUNT 和 LIMIT/OFFSET，权限和全部生效筛选先于分页。
- 前端输入仅保存草稿；点击/回车每次执行一次当前页请求，同词重复搜索也请求；翻页、页容量和筛选条件更改均请求后端，搜索/筛选重置到第一页。公共列表缓存与选择器不使用搜索结果覆盖。
- 智能体使用 `/api/advisor/agent-overview` 将正式智能体/草稿在SQL UNION后统一排序分页，分别遵守各自权限，不再客户端拼接全表。知识库文档独立分页，详情 `includeDocuments=false` 不附带全量文档。
- 过滤条件：工具permission、技能status、模型kind/provider、用户status/roleId、角色status/code、文档status，均由后端SQL处理。默认模型摘要 `defaultModel` 独立于结果保留。
- 旧无page接口仅为既有选择器保留兼容；管理列表不再调用它实现分页。
- 提示文案统一搜索+对象，去掉长句。
