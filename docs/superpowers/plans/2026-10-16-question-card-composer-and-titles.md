# 追问卡片替换输入区与短标题实施计划

## 范围与交互

- 有待回答问题时，现有 QuestionCard 在 ComposerDock 内替换普通输入部分，宽度及边距一致；共享队列保留，排队消息仍可查看和取消，追问期间不从队列直接发送。
- 单选、多选、自定义答案、折叠、提交失败重试继续复用现有卡片。提交成功并确认问题已回答后恢复普通输入区；原草稿和附件保存在父组件，切换期间保留。
- 运行尚未结束但已出现问题时卡片禁用答案，并保留停止入口；不能因为隐藏 ComposerDock 丢掉停止能力。

## 标题与内容契约

- `report_question` 增加可选 `title`，生成规则为简短、专业、动态的待决策事项，建议 6–18 个中文字、硬上限 40 字符，不复述用户、不写自述、不枚举选项。
- 现有 `text`、选项与回答接口保持不变；新事件携带简短 `title`，完整 `text` 仍用于答案快照及模型恢复。现有旧签名保留委托，历史记录不重写。
- 服务端校验显式标题长度与单行约束；缺少标题时从原问题首句截取，超长明确省略。前端对旧记录使用相同展示兜底，不生成新事实或替换原问题。
- 卡片按“短标题 → 必要说明 → 1…N 选项 → 自定义答案/提交状态”展示。长说明默认收进问题说明，不占用标题滚动区；选项顺序以真实数组为准，继续用圆形数字标签。
- 只扩展应用层可选字段，不改 SDK 公共事件结构、数据库结构、权限与请求幂等机制。

## 验证

- 前端：有问题时普通输入框隐藏，提交后恢复，失败答案保留，已有草稿恢复，运行中仍可停止；长标题、显式标题、历史记录与原文说明完整保留。
- 后端：短标题与完整问题分离、拒绝超长/多行显式标题、旧参数兼容、提交快照保留完整问题，工具 schema 含标题且持久化后才推送。
- 相关 Vitest、全量前端、Lint、TypeScript/Vite；QuestionService/ReportActions/会话控制器相邻测试及 Spotless。双语 docs/v2 同步。
- 不启动浏览器，不启停应用后端，不修改运行数据，不提交或推送。按组件显示与可选标题字段分别可回退。
