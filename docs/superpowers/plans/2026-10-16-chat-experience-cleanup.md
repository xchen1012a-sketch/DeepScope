## 一、目标与最终交互

对话以用户输入和最终正文为主；过程轻量、实时、可按需展开。移除无明确文件位置的“交付物/已归档”阶段和内部事实编号。子智能体以任务名称、真实状态、当前步骤及可查看的执行内容呈现。

```text
用户问题

  正在分析…                   ← 灰色文字，紫色轻量动态指示
  模型当前说明文字             ← 颜色较深，实时追加
  ▸ 分析记录                  ← 点击在当前位置展开
  ▸ 运行命令 · 检查项目        ← 浅色操作文字
  ▸ 子任务：检查依赖 · 执行中   ← 可查看该子任务实时过程

  用时 2分钟 18秒 ▸           ← 完成后可折叠过程，无额外失败计数

最终回答正文                    ← 无交付卡、归档声明或F/E引用标签

[输入消息，支持多行与内部滚动                         ]
  ＋                     模型 ▾   小尺寸上下文环   发送
```

图示为层级和交互说明，沿用项目现有组件，不新增一套聊天 UI 框架。真实失败、等待确认和任务终态仍如实记录，去掉的是重复、额外的失败提醒。

## 三、执行顺序

### 阶段1：先做纯前端样式调整

对应需求：3的圆圈尺寸、5的颜色区分、6的额外提示。

1. 上下文圆环由28px缩小至约16–18px，视觉与发送按钮明确区分；保留足够的点击/聚焦区域和用量气泡。
2. 模型输出说明和最终正文使用现有深灰文字；工具行、分析入口、自动动作说明使用浅灰，不为不同类别堆叠彩色标签。
3. 移除“有调用失败”“1项失败”等整轮/批次附加提示，不新增 Toast 或告警。单项状态与详细错误仍如实保留；用户需要确认的卡片、整轮失败/中断反馈不改成成功。

主要文件：`ContextRing.tsx`、`ComposerDock.tsx`、`TurnGroup.tsx`、`ActionBatch.tsx`、`ToolLine.tsx`、相关词典与测试。

验收：圆环视觉缩小但用量查看仍可操作；正文与过程层次清楚；整轮/批次没有重复失败标签；实际状态及详情没有被篡改。

### 阶段2：调整思考交互和滚动机制

对应需求：3的滚动、4、7。

1. 分析记录在原位置展开/收起，`aria-expanded` 与内容同步；不再因点击分析行自动打开侧栏。
2. 执行中展示服务端实际返回的思考增量，不等结束再显示；用户手动收起后保留选择，不因每个增量强行展开。
3. 恢复紫色轻量滚动/流动效果作为当前思考状态指示，思考文字保持灰色、正文深灰。不同时让每条历史记录持续运动；停止、等待确认、完成或失败后停止动画，支持系统减少动态效果。
4. 思考长文本使用现有有界文本展示和内部滚动；处于底部时跟随新内容，用户上翻后停止跟随，回到底部后恢复。保留已有完整内容，不只保留最后一段。
5. 输入框单行起步、随内容增高，到既定上限后内部滚动；滚轮位于输入区时优先滚动输入内容，边界不意外带动整个对话。普通消息区仍按原逻辑滚动。
6. Enter发送、Shift+Enter换行、中文输入法组合键和长文本粘贴保持正确；扩展输入高度不遮挡发送/停止入口。

主要文件：`ThinkingLine.tsx`、`ProcessText.tsx`、`ProcessStatusLabel.tsx`、`processMotion.ts`、`ConversationPanel.tsx`、`ComposerDock.tsx`、`conversationScroll.ts`、`index.css`。

验收：流式思考在当前位置持续可见；展开分析不出现侧栏；手动阅读不被拖回底部；动画只作用于当前活动区域，文字不变紫色；输入滚动不串到对话区。没有服务端思考内容时仅显示状态，不伪造思考文本。

### 阶段3：取消交付物阶段，处理新旧会话

对应需求：1。

1. 核对 `report_deliverable` 的工具注册、自动生成行为文件和实际工作区提示词来源，取消“必须交付/归档后才结束”的要求，允许主智能体直接输出最终正文。
2. 不再生成新的“交付物”“已归档”卡片或无实际位置的归档承诺。真实文件产出沿用现有文件/附件入口，展示可访问的位置，不增加新的交付阶段。
3. 对旧客户端或已有智能体仍可能调用的旧工具，保留最小兼容路径，返回语义不再宣称归档；新的工具暴露/提示流程不鼓励继续调用。
4. 历史 deliverable 如果只是重复元信息，隐藏独立卡片；如果里面有唯一结论正文，转为普通正文展示，不直接删除内容或重复展示两份结论。
5. 数据库历史记录不清理、不批量改写。用户自定义工作区文件不覆盖；对自动生成的旧规则，先识别归属及适用范围，再采取受控兼容方式。

主要文件：后端 `ReportActions.java`、`AgentProvisioner.java`、相关工具注册/工作区行为约定；前端 `model/blocks.ts`、`ConversationPanel.tsx`、`TimelineCard.tsx`、现有交付展示组件与回放测试。

验收：新对话直接形成最终回答；不会出现“交付物已归档”却无位置的承诺；历史会话的唯一结论、真实附件不会丢失；刷新后结果一致。

### 阶段4：子智能体状态与内部标签治理

对应需求：2，关联实时状态链路。

目标交互参考 Codex 的任务查看方式：以任务而非事实编号作为入口；列表显示任务名称、简短目标和真实状态。点击查看任务自己的实时过程，完成后查看结论及来源，可返回任务列表。

```text
子智能体

[检查依赖风险]   执行中 · 正在读取依赖配置       [查看]
[检查权限边界]   已完成                         [查看]

查看某任务：
‹ 返回任务列表
检查依赖风险 · 执行中
当前步骤 / 已返回说明 / 工具记录 / 最终结果
```

1. 调整汇报工具和主/子智能体提示约定，不要求生成 F1/E1 等用户无意义的编号，不把“事实回流编号”当作状态展示。
2. 前端事实和来源列表不显示内部ID徽标；正文不再将 `[F3]` 变成按钮。内部追踪ID可保留用于关联和去重，但不对用户呈现。
3. 对历史正文仅处理明确的内部引用标记：例如已知事实ID的引用按钮、`[F12]`/`[E3]` 或已确认的编号前缀。不能全局删除所有 E/F加数字的字符串，避免误伤错误码、型号、路径、代码、代码块及技术原文。
4. 保留事实来源与结论文本，缺少来源时不编造。对“正文裸编号”优先从提示词来源消除，历史兼容必须依据上下文确认，不能盲目正则替换全文。
5. 复用现有子智能体事件累积、分页接口和只读详情，核对状态从派发、运行、完成、失败、停止到超时的映射；“已派发”不代表已完成，旧运行快照不能覆盖终态。
6. 实时查看先复用现有流式事件；若详情需要补齐持久化过程，则仅对活跃且可见任务做有界刷新。没有更新不伪造进展，关闭或切换后停止无关刷新，历史列表保留分页。
7. 流式展示、运行收尾、刷新回放沿用同一任务身份，避免重复任务、丢步骤或把最终结果回退成运行中。

主要文件：前端 `Markdown.tsx`、子任务卡片/详情、`ProcessPanel.tsx`、`subagentSteps.ts`、`useAdvisorConversation.ts` 的展示投影；后端 `ReportActions.java`、`SessionProcessProjector.java`、`AdvisorSessionController.java` 与现有子任务事件链路。仅在核对后确有缺口时调整具体链路。

验收：截图中的 F26/F27 等徽标消失；已知内部引用不进入正文，合法技术 E/F字符串保留；子任务可按名称和真实状态查看实时过程；派发、终态、刷新和分页一致。

### 阶段5：整体验证、文档与交接

1. 每阶段先写行为测试并确认失败，再做最小修复。样式/静态文案不添加机械镜像测试；优先验证用户操作、状态和数据保留。

7. 不擅自 commit/push、清理混合工作区或删除历史数据。服务更新放在代码与门禁完成后处理，当前仅计划阶段不执行。

## 四、契约与实施边界

- 初期不新增接口、不修改数据库；优先使用已有事件、分页和详情数据。确需跨前后端新增字段时，先在本计划补齐字段含义、事件时机、旧数据回退和验证用例，再实现两端。
- 交付阶段移除是产品展示和工具约定调整，不等于删除已存结论或真实文件。
- “调用失败不额外提示”是取消重复汇总提示，不等于把失败显示成成功或吞掉需要用户处理的确认/中断。
- 思考实时展示只消费模型实际输出；不额外发模型调用生成动画文案。
- 全部复用现有 React、Radix、Tailwind、TanStack Query 及执行过程组件；不增加依赖，不模仿未经核实的 Codex 内部实现。
